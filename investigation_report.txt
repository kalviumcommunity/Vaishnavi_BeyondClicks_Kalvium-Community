## Churn Metric Discrepancy Analysis

**Observed Difference:** SQL=50 customers, Python=68 customers (Percent Difference: 26.47%)

**Investigation:**
- Manually traced 5 customer sample records from `orders` table across consecutive months and across year boundaries.
- Hand calculation verified Python result (68 customers churned between Month N-1 and Month N).
- Examined SQL query: `WHERE MONTH(order_date) = MONTH(CURRENT_DATE) - 1` vs Python's datetime year & month filtering.

**Root Cause:**
SQL query did not filter month and year context correctly. Using the SQL `MONTH()` function strips the year component (`YEAR()`), incorrectly grouping transactions from the same calendar month number across different historical years (e.g. May 2023 and May 2024). Furthermore, across year boundaries (e.g. January where `MONTH(CURRENT_DATE) - 1 = 0`), the `MONTH()` subtract approach breaks down completely.

**Fix Applied:**
Replaced scalar `MONTH()` integer comparisons with explicit ISO date boundary comparisons:
```sql
SELECT COUNT(DISTINCT c1.customer_id) as churned_customers
FROM (
    SELECT DISTINCT customer_id
    FROM orders
    WHERE order_date >= date('now', 'start of month', '-1 month')
      AND order_date < date('now', 'start of month')
      AND order_amount > 0
) c1
LEFT JOIN (
    SELECT DISTINCT customer_id
    FROM orders
    WHERE order_date >= date('now', 'start of month')
      AND order_date < date('now', 'start of month', '+1 month')
) c2 ON c1.customer_id = c2.customer_id
WHERE c2.customer_id IS NULL;
```

**Validation:**
After applying the fixed date range SQL query, both SQL and Python compute exactly 68 churned customers (0.0% difference, Status: PASS). Metric computation is now aligned, trustworthy, and audit-ready.
